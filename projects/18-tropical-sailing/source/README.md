# PELAGIC · 海湾航记

一个由代码生成的 Three.js / WebGPU 热带海湾：40 米木质双桅帆船、多方向谱海浪、九点浮力、GPU 持久尾流、近岸泡沫与湿沙。

## 启动

需要 Node.js **20.19+** 或 **22.12+**（开发验证使用 Node 24.16.0），以及支持 WebGPU 的近期 Chrome / Edge 和可用显卡驱动。

```sh
npm ci
npm run dev
```

打开终端给出的 **localhost** 地址。浏览器需要开启硬件加速。一般 HTTP 局域网 IP 地址不是安全上下文，请用 localhost 或 HTTPS。

```sh
npm run check   # JavaScript 语法检查
npm run build   # 生产构建，同时生成独立 HTML
npm run preview
```

`three` 精确锁定为 **0.180.0**，`vite` 为 **7.1.7**；同时交付 `package-lock.json`。项目不需要后端服务，不读取模型、贴图、字体、HDRI 或 CDN 资源。

## 单文件版本

项目旁的 **海湾航记.html** 已内嵌 Three.js、所有场景代码和 CSS。建模、木纹、帆布纹理、海底和植被都在本地生成，运行时无需联网。

在支持 WebGPU 的 Chrome / Edge 中直接打开该文件。若浏览器对 `file://` 禁用 GPU 或安全上下文，请用本地静态服务器打开这个同一文件；例如在 HTML 所在目录执行：

```sh
python -m http.server 8000 --bind 127.0.0.1
```

然后打开 `http://localhost:8000/海湾航记.html`。缺少 WebGPU 时会显示中文原因和恢复方法，不静默退回 WebGL，也不显示空白页。

`npm run build` 会在项目的上一级目录重新生成 `海湾航记.html`。`dist/` 是普通网站版本；两者由同一源码生成。

## 操作

| 操作 | 效果 |
| --- | --- |
| 风速 0–18 m/s | 连续调整波幅、破碎、泡沫、浮力响应与帆的鼓起程度；波相位不重置 |
| 航速 0–12 kn | 设置目标航速，船逐渐加减速；1 kn = 0.514444 m/s |
| 太阳高度 5–78° | 从暖色低日照过渡到热带白天；光照、水色、反射一起变化 |
| 拖动 / 滚轮 / 右键拖动 | 旋转 / 缩放 / 平移；手动操作后退出镜头跟随 |
| 海湾 / 追船 / 水线 / 俯瞰 | 平滑切换机位，并恢复跟随 |
| A / D，或左 / 右转向按钮 | 轻点改变目标航向约 7.5°；按住持续转向，船舵渐进响应 |
| 跟随 | 切换自由镜头与船舶跟随 |
| 空格 | 暂停 / 继续模拟；暂停时仍可操作镜头 |
| R / 复位 | 船回到海湾起点，清除旧尾流，恢复海湾机位；保留滑杆设置 |
| H | 隐藏 / 恢复界面 |
| 留影 | 下载当前三维场景 PNG，不包含操作面板 |
| 右上角 ⓘ | 查看作品和操作说明 |

默认航向控制会保持目标航向，并受水面力矩影响。在水深不足的前方会减速并渐进转开。默认航行会逐渐离开起始海湾，按 R 返回；没有无限重复的岛屿。

## 海浪方法和真实量级

- 所有长度以米计，重力 `g = 9.81 m/s²`。船壳约 39–40 m，总长含斜桅约 48 m，最大船宽 10 m，主桅顶约 32 m。
- **不是 FFT**：使用 48 个固定随机种子、多方向、不整齐间隔的 Gerstner 谱分量，波长约 **1.6–180 m**。JONSWAP 形状权重使用 `α = 0.0081`、`γ = 3.3`、`ωp = 1.03 rad/s`，峰值两侧 `σ = 0.07 / 0.09`，叠加少量长涌浪尾部权重。
- `ω² = gk`，相速 `c = √(g/k)`，长波传播更快。没有把不同波长全部设置为同一传播速度。
- 归一化基准高度 RMS 为约 0.48 m；风幅系数为 `0.055 + (U / 9)^1.65`。界面的浪高是未计局部水深和网格过滤的**深水有效波高估算值** `Hs ≈ 4 × RMS`，不是实测峰谷差。
- 风速通过时间常数约 1.43 s 的低通过渡，只改变振幅与尖峰强度，不改变既有频率和相位。0 m/s 仍保留约 0.1 m 的残余涌浪。
- 横向余弦位移与垂向正弦位移共同构成尖峰；GPU 同时计算两个切向量和水平位移 Jacobian，用于法线和破碎判据。
- 320 × 320 格海面采用中心均匀、外围连续扩展的同一网格，约 20.5 万三角形。中心步距约 1.375 m，外围覆盖十余公里。频谱按实际顶点间距平滑低通；片元微波纹还按屏幕像素足迹和距离过滤，避免粗网格混叠及硬 LOD 接缝。

## GPU / CPU 分工

**实际在 GPU 上执行：**

1. 主海浪的谱求和、水平位移、切向量、法线和 Jacobian。
2. 尾流有限差分传播、压力源注入、泡沫生成 / 扩散 / 衰减、岸边湿润状态。
3. 浮力采样点的水平位移逆解和谱水面加尾流高度读取。
4. 光谱吸收近似、菲涅尔、GGX 太阳高光、天空反射、程序化焦散和泡沫细节。

使用 `Three.WebGPURenderer`、TSL `storage`、`Fn().compute()` 和 `wgslFn`。CPU 负责初始化固定波谱参数、建模、输入、九点力与力矩的刚体积分，以及提交 GPU 工作；没有用 CPU 假装更新一张动态尾流贴图。

## 浮力如何读取同一水面

- 船底前、中、后三排共 **9 个采样点**，横向位于 `x = -2.65 / 0 / 2.65 m`，纵向 `z = -12 / 0 / 12 m`，基准深度 `y = -1.65 m`。
- 船体的旋转矩阵先把采样点转换为世界坐标。GPU 使用与顶点着色器相同的波谱函数和同一持久扰动缓冲区，迭代 5 次反解水平 Gerstner 位移，再读取对应水面高度。
- 通过 `renderer.getArrayBufferAsync()` 每秒最多回读 30 次，每次 9 × vec4，共 144 B。回读是异步的，CPU 使用最近完成的数据，通常会有一至数帧延迟；不是零延迟同步读取。船旁网格对解析曲面的插值也有离散误差。
- 质量 165 t。按每点浸没量计算浮力与局部垂向阻尼，累加重力及俯仰、横摇力矩；以固定 `1/60 s` 步长积分。帆的风压力矩带来平均横倾，局部水面坡度产生偏航扰动，舵力矩负责航向控制。
- 升沉 / 俯仰 / 横摇 / 偏航均不使用预设 `sin(time)` 摆动。帆布的小幅边缘 flutter 是独立材质效果。
- 海面片元用船的实时位置、航向、俯仰、横摇和船壳截面做内部裁切，避免把外部海面直接画进船内。它是船壳内部遮罩，不是完整的自由液面与船壳接触求解。

## 尾流和跨帧状态

- 两个 **256² × vec4** GPU StorageBuffer 交替读写，占约 **2 MiB**。每格 2 m，覆盖随船移动的 512 × 512 m 区域。
- 四通道分别保留扰动高度、扰动垂向速度、泡沫浓度、岸边湿润记忆。缓冲区按整格跟随船，并以旧的世界坐标读取上一帧；旧航迹保留在世界位置，转向后自然形成弯曲航迹。
- 船首正 / 负压力源、近船尾约 19.5° 的两臂源和中央泡沫源由船的**实际速度平方**驱动。只在船周围注入；远处尾迹来自历史状态，不是每帧重新画出的无限长 V。
- 扰动满足阻尼波动方程的二维有限差分近似。`c² = clamp(g × depth, 4, 85)`；传播、阻尼和泡沫扩散都逐步积分，边缘用吸收带消除明显反射。
- 泡沫时间常数约 7.5 s，湿沙约 22 s。破碎从水平 Jacobian 压缩与波峰高度触发；岸边从局部水面与海床相交、浅水破碎触发。风平浪静且船停下后，船尾源趋零，既有扰动和泡沫渐渐散去。

## 浅滩、海床与水色

- 三座岛屿和一段浅礁由同一 `bathymetry.js` 函数从约 -28 m 海床升起。该模块生成 JS 与 WGSL 两份同源表达式；可见地形、吸收水深、近岸计算和避浅判断共享地形定义。
- 近岸用深度相关振幅增益模拟 shoaling，再限制浅水振幅。水面与海床相交形成往复水线；泡沫和湿润程度使用 GPU 跨帧场，不是随机刷白海岸。
- Beer–Lambert 形式吸收为 `exp(-σ × opticalDepth)`，线性 RGB 通道系数约为 `(0.22, 0.072, 0.039) m⁻¹`，红光吸收更快。海底颜色和程序化焦散随水深衰减，深水过渡到蓝绿色散射。
- 水的 `F0 = 0.0204`，Schlick 菲涅尔反射程序化大气天空；GGX 太阳镜面项配合微法线产生闪烁光点，另有浪峰薄处透光近似。泡沫以有细节的部分覆盖混合，不是整片纯白面。
- 天空、太阳和海上薄雾使用解析近似，配合 ACES 色调映射。木船、帆布、岩石和植被使用独立粗糙度及阴影；木纹与帆布纹理来自生成式 Canvas 绘制，无外部图片。

## 性能取舍与已知局限

- 这是实时视觉与近似水动力实验，不是 CFD、海况预报、航海训练或精确船舶稳性模型。
- 48 个离散谱分量比高分辨率 FFT 便宜，长时间、特殊机位下仍可能看出有限频率结构。参数变化不重建平衡谱，峰值周期保持不变，这是相位连续性的取舍。
- 海岸只模拟幅度变化、破碎泡沫、湿沙和浅水扰动传播；**没有完整的波浪折射、折射后的相位求解、三维卷浪或岸上水体体积守恒**。
- 透明感来自共享海床的程序化光学计算；未进行真实屏幕空间折射或水下场景捕获，因此水下石块、船体倒影不完整。天空反射是解析的；没有全场景反射或路径追踪。焦散不是光线追踪求解。
- 尾流是二维标量波场与有限范围泡沫状态，2 m 分辨率不能解析船壳湍流、小涡流和飞溅水滴。离开跟随场的泡沫历史会被舍弃；远岸不持有全世界的海岸状态。
- 浮力使用九点、简化排水体积、独立轴转动惯量和异步读取，不模拟完整六自由度刚体碰撞或帆船动力学。航速是用户指定的动力目标，风不直接决定目标航速；风通过海浪、帆形和横倾间接影响局部尾流。
- 强风全帆仍保留可操作性，没有自动缩帆、翻船、搁浅碰撞和损伤系统。极端近看可发现接触遮罩与离散网格的误差。
- 像素比上限 1.5；静态船体索具按材质合批，植被 / 礁石合批或实例化。每帧最多追赶约 67 ms 的模拟时间，后台标签暂停推进，防止恢复时物理爆炸；低帧率时不会按墙钟完整追赶全部时间。
- 已检查当前环境的功能与短时稳定性；没有做多显卡兼容矩阵、全天压力测试或性能保证。WebGPU 设备丢失会显示恢复提示。

## 验证

详见 `VALIDATION.md`，其中区分已执行检查与未验证部分。所有模型和材质由源码生成，交付物含完整源码、锁文件、构建输出、许可证及这个说明。

开发诊断：在地址末尾加 `?verify=1`，会每隔约 4 秒读取持久场统计并写入 `#app[data-field]`，包含 `invalidCells`、扰动峰值、泡沫总量及采样次数。`#app[data-simulation]` 为当前状态。普通模式不执行这个额外场回读。不要把本地帧率瞬时读数当成跨设备基准。
