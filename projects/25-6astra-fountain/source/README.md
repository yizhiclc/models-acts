# 涌泉庭园 · GIARDINO

一个由代码生成的古典庭园喷泉。使用 **Three.js 0.180.0 的 WebGPURenderer、TSL 材质和原生 WGSL compute**，不依赖后端、CDN、外部贴图或现成场景模型。

## 安装与启动

需要 Node.js **20.19+ 或 22.12+**，以及支持 WebGPU 的浏览器和图形设备。推荐通过 localhost 或 HTTPS 打开。

```bash
npm ci
npm run dev
```

打开终端给出的地址，默认是 `http://127.0.0.1:5173`。首次启动会编译着色器，并在 GPU 上预运行三秒的水流，使页面直接呈现正在运行的喷泉。

```bash
npm run build
npm run preview
```

`dist/index.html` 是普通生产构建的入口；部署时应连同 `dist/assets/` 一起提供。开发服务仅绑定本机。

### 单文件 HTML

每次 `npm run build` 同时生成：

- `dist/fountain-single.html`
- 项目父目录的 `fountain-single.html`

该文件约 1 MB，内嵌 Three.js、业务代码、WGSL 和 CSS，不需要相邻资源文件，也不使用 CDN。可直接尝试用支持 WebGPU 的浏览器打开；不同浏览器对 `file://` 的 GPU 权限有差异，可靠的打开方式是通过本地静态服务器：

```bash
npm run single
```

打开 `http://127.0.0.1:4174`。这个单文件预览脚本只使用 Node 内置模块。复制单文件到其他静态服务器也可以。

## 尺度与构图

场景单位为米。圆池外径约 **7.28 m**，池沿高 **0.79 m**；两层水面分别位于 **1.925 m、3.215 m**，中央喷口高 **3.476 m**。默认水柱顶点约 6 m；强劲档可达到约 6.6 m。理想喷口上升高度为 `v²/(2g)`，实际数值还受到阻力、扰动影响。

池沿、基座、柱身和水盘采用闭合旋转体剖面，包含收分、卷口、线脚和浮雕感装饰；八个狮首喷口、涡卷、瓣状水盘肋均由代码建模。庭园包含十字轴线与环形铺装、四块修剪花坛、花、乔木与柏树、三张长椅、石栏杆、门柱、花盆和铁门。石材和草地使用程序噪声，池底有程序瓷砖图案。静态建筑按材质合并，植物使用实例化。

## 水如何计算

### 持续 GPU 状态

`particles.wgsl` 在 storage buffer 中保存 **98,304 个水粒子槽位**：65,536 个主水流采样，32,768 个脱落水滴与飞溅采样。并非所有槽位在每个时刻都存活；典型运行中约有两万至两万七千个活跃水团。

每个水团保存位置、年龄、速度、阶段、半径、发射器编号、体积和出生时刻。以 **1/120 s 固定步长**进行半隐式积分，叠加重力、按尺寸区分的空气阻力、侧风、时变小扰动与碰撞。出生时才设置喷口状态；飞行中不根据时间重建抛物线，调节参数也不会重置现存水粒子。

一个计算步依次执行：

1. 根据上一时刻真实碰撞的输入量，更新水盘蓄水、溢流和泵/风的平滑状态。
2. 更新主水流，写入碰撞事件、冲击网格和入水计数。
3. 单独 dispatch 更新脱落水滴和飞溅。它只读取已经完成的主水流状态，避免跨工作组读写竞争。
4. 更新三个水面高度场，交换波动状态。

GPUBuffer 同时供原生 WGSL compute 和 Three.js 的只读 TSL storage 节点使用。普通动画循环没有粒子 CPU 回读，也不会每帧上传粒子位置。`simulation.js` 中只有一处与 Three 后端 buffer 共享有关的内部接口，因此 `three` 固定为 **0.180.0**，不建议直接取消版本锁定。

### 连续水束与破碎

128 条发射采样通道使用环形状态缓冲，每通道每步发射两个有时间间隔的水团。顶点着色器连接**相邻出生、仍存活且尚未碰撞的实际 GPU 位置**，形成动态水带。跨生命周期、发生反弹、距离异常的连接会被切断。

水带从喷口到顶点逐渐变细。下落阶段叠加沿速度拉伸、尺寸各异的透明水滴；主水流还会向独立水滴系统脱落采样。水带的顶点来自积分后的状态，不存在预先定义的透明管、曲线水柱或滚动水纹。水盘溢流使用切向展开的薄片，同样由这些运动状态决定。

### 结构碰撞与溢流

下降的水团使用连续跨面检测，按从上到下顺序寻找最先碰到的水盘或底池。中央柱体使用分段旋转包络，盘沿使用环形截面，底池内壁和上表面使用环形碰撞约束。碰撞可吸收入水或产生少量反弹，并记录真实位置与时间。

原始水团的体积通过原子计数进入上、下水盘的有效蓄水库；二次飞溅不会重复增加体积。溢流量由超过堰口的有效水量计算，经过质量收支更新，影响后续薄水幕的体积和宽度。上层的八组溢流口落入下层，下层再流入底池。底池视作循环泵的供水库。

这是一套针对喷泉的简化水力模型，使用解析碰撞包络，并非全场 SPH 或不可压缩 Navier–Stokes 求解器。

### 落水反馈与涟漪

三个水面分别拥有 **128 × 128** 网格，存储高度、垂直速度与泡沫。真实碰撞使用整型原子操作写入相应网格。冲击核中心下压、邻域上抬，权重和为零，避免连续落水使整个水面单向下沉。

`waves.wgsl` 求解带阻尼的二维波动方程；邻域交换让涟漪传播和叠加。池沿及柱体边界采用零法向梯度，使波产生反射。不同水盘的传播速度与网格间距匹配，固定步长保持数值稳定。泡沫由同一碰撞能量产生并衰减。局部冲击事件还生成短暂水冠和小圆环；它们是高度场之外的近场视觉细节，而非水面波动的替代。

### 透明、高光、反射与折射

水团使用软边、透明的水带和速度拉伸面片，不是等大的不透明球。着色根据视线、阳光方向、虚拟曲面法线和微小表面变化计算高光、边缘反射与逆光透光。

底池有实时平面反射，包含庭园、喷泉和树木。独立的不透明场景渲染通道为折射提供颜色；GPU 高度场的法线扰动折射与反射采样，因此可以透过水看到池底瓷砖。上层水盘采用天空近似反射。夜间打开六盏池底灯和两盏中央上照灯，同时调整环境光与水体受光颜色。

## 验证与调试

在 URL 后附加 `?diagnostics=1` 可显示“读取 GPU 状态”按钮。按下时才进行 GPU readback，显示活跃数量、最高水滴、波动能量、蓄水/溢流和最近落点的重心。也可在开发者控制台中运行 `await window.__fountain.snapshot()`。这些回读均不参与动画。

实际验证记录见同目录 `VERIFICATION.md`。当前实现已运行构建和真实浏览器 WebGPU 检查；跨浏览器、不同显卡和实体移动设备尚未全面测试。

WebGPU 缺失、适配器创建失败、设备丢失或着色器运行出错时，页面会给出可读提示及重试按钮，而不是仅呈现空白画布。

实现接口参考：[Three.js WebGPURenderer](https://threejs.org/manual/pages/webgpurenderer)、[StorageBufferAttribute](https://threejs.org/docs/pages/StorageBufferAttribute.html)。
