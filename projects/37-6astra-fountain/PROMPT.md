# 原始提示词

【任务】

请用 Three.js 和 WebGPU 创建一个可运行、可交互观察的古典庭园喷泉 3D 场景:一座石质多层喷泉位于安静的小型庭园中央,水从喷口喷出,在空中形成连续的水柱与散射,落入水盘和水池,并持续循环。重点是水:近看有细节和质感,中远看是连续的一股股水,而不是一堆分离的小点。

【喷泉与庭园】

1. 喷泉取真实量级(单位为米):底池直径约 6～8 米,总高约 4～6 米,中央水柱高度约 2～4 米。造型为古典风格,包含:八角或圆形石质水池及池沿、中央柱体、至少两层水盘、雕刻感装饰，如涡卷、花环、狮首或海豚形出水口。柱体和水盘用旋转体轮廓加线脚建模,而不是简单圆柱堆叠。细节可适度概括。
2. 庭园围绕喷泉组织:石板铺地与草地的边界、修剪的矮篱或灌木、花、几棵树、长椅、矮墙或栏杆,有中轴或环形步道。喷泉不能孤立摆在空地上。元素数量自定。
3. 默认为晴朗午后或傍晚,低角度暖色阳光,喷泉处于半逆光,使水花产生高光和透光。打开页面即可看到完整喷泉与庭园。

【水体】

1. 水粒子的位置、速度、寿命在 GPU compute 中更新(storage buffer),规模从数万到数十万自定。
2. 水的形态应分层,而不是全程同一种粒子:
   - 喷口处水柱连续、厚实,喷口速度、角度和口径决定射程与高度(高度应与 v²/2g 大致相符);
   - 接近顶点时水柱变细、抖动,边缘开始脱落水滴;
   - 下落阶段拉伸成细雨般的水滴,在落点附近集中;
   - 至少有一处出水口不喷射,而是溢出,沿水盘边缘形成薄水幕,跌入下层水盘或水池。
3. 落水反馈:水落到水盘和水池时,在落点产生环形涟漪、小水冠和泡沫;涟漪在水中传播、相互叠加、被池沿反射并逐渐衰减(GPU 高度场或等价方法)。落点密集处扰动强,稀疏处较平静。
4. 水与结构:粒子不得穿过水盘、柱体和池沿(简化碰撞体即可)。上层水盘的溢流位置决定下层的落点,溢流量与落入水量相关。
5. 风:轻微侧风使细水滴和水雾偏移,落点随之改变,主水柱只发生轻微偏转。
6. 渲染:水粒子不能是等大的不透明圆球。可采用沿速度拉伸的面片、屏幕空间融合、条带、metaball 等,方案自定。要求半透明,有随光线闪烁的高光,逆光时透光,边缘柔和。水池水面反射天空、喷泉和树木,并折射池底。

【交互】

1. "水势"滑杆,从柔和到强劲。变化时喷口速度、流量、水柱高度、射程、落水扰动、飞溅量随之变化,水体重新形成新的状态,而不是把整条水柱等比缩放。
2. "风力"控制。
3. 时间控制(白天到黄昏到夜晚)。夜间有水下灯,从下方照亮水柱和水盘。
4. 支持旋转、缩放、平移和复位,预设至少 3 个机位(全景、水盘近景、贴近水面)。

【实现取向】

优先保证:水的观感与运动连续性、喷泉造型与庭园的整体协调、落水与水面反馈、GPU 粒子的实际运用。

判定标准是行为:水柱和落点由 GPU 上跨帧的持续状态演化产生,水势或风改变后重新演化。以下情形视为未满足要求:所有粒子独立重复同一条抛物线且落点固定;水面涟漪是与落点无关的循环动画;水柱是透明管、曲线或滚动纹理;用大量雾和小点掩盖主水柱不成立。

【技术要求】

- 使用 Three.js WebGPURenderer(TSL 或 Compute 均可),粒子更新和水面波动的核心计算运行在 GPU 上;WebGPU 不可用时给出提示而不是白屏。
- 所有模型和材质由代码生成,不加载现成的喷泉场景。React 或原生均可,无需后端。
- 在工作区创建完整项目,可用 Vite,确保安装后可直接构建启动,并在 package.json 中锁定 three 版本。
- 页面打开后直接看到正在运行的完整场景,动画与视角操作保持稳定流畅。
